Direction lock

This is not a standard SaaS split hero. The approved pattern is sparse and experiential: floating nav, huge top-left statement, restrained CTA pair, and one large lower interactive viewport that carries the product proof.

Use

Minimal layout, strong negative space, proof tiles, scroll depth, viewport-aware composition, real HTML text.

Avoid

Dashboard mockups, browser-card grids, left-column/right-image split, fake metrics, generic agency sections, copied PeachWeb assets.

Palette

Graphite, smoked charcoal, cyan action, teal support, soft depth blue. Analogous cool harmony only.

Dynamic viewport resolver

Responsiveness must respond to viewport shape, not only width. The implementation should read horizontal size, vertical size, aspect ratio, visual viewport height, and available space.

ModeTrigger ideaDisplay behavior
wide-desktopLarge width and landscape aspectHuge lower viewport, three proof tiles in depth, full parallax.
portrait-desktopTall desktop or narrow aspectHero height capped; proof tiles stack 2+1; less empty space.
tabletMedium width / mixed aspectCompact nav; lower stage taller; reduced parallax.
mobile-tallSmall width with enough heightOne featured proof tile; step/swipe affordance; CTA visible.
mobile-shortSmall width and limited heightCompressed headline, reduced motion, proof stage peeks into view.
 
const root = document.documentElement;

function resolveViewportMode() {
  const vw = window.innerWidth;
  const vh = window.visualViewport?.height || window.innerHeight;
  const aspect = vw / Math.max(vh, 1);
  const reduced = window.matchMedia('(prefers-reduced-motion: reduce)').matches;

  let mode = 'wide-desktop';
  if (vw < 640 && vh < 680) mode = 'mobile-short';
  else if (vw < 640) mode = 'mobile-tall';
  else if (vw < 980) mode = 'tablet';
  else if (aspect < 0.9 || vh > vw * 1.2) mode = 'portrait-desktop';

  root.dataset.viewportMode = mode;
  root.dataset.reducedMotion = reduced ? 'true' : 'false';
  root.style.setProperty('--vw', `${vw}px`);
  root.style.setProperty('--vh', `${vh}px`);
  root.style.setProperty('--aspect', aspect.toFixed(3));
}

Motion plan

GSAP motion should explain the product, not decorate every element. The opening sequence stages the story: brand, promise, CTA, then proof viewport.

Opening

Nav appears, headline settles, CTAs enter, lower proof stage rises into partial view.

Scroll

Proof tiles become the focus; depth and parallax are mode-specific and reduced on mobile.

Reduced motion

Disable parallax and long transitions; keep proof tiles readable and fully accessible.

Implementation tasks

Build in layers: static first, responsive resolver second, motion third, then proof polish and QA.

1. Static hero

Astro component with real text, nav, CTA, and lower proof-tile viewport. No animation dependency.

2. Resolver

Add viewport-shape detection and mode attributes. Drive CSS variables from measured dimensions.

3. GSAP

Add mode-specific hero reveal and scroll focus timelines. Rebuild safely on mode changes.

4. Tile interaction

Desktop hover/focus depth; mobile step controls; keyboard accessible proof navigation.

5. QA

Build, screenshot desktop/mobile, reduced motion, overflow check, social preview frame.

6. Asset upgrade

Only add Spline/R3F/Higgsfield textures if the HTML/CSS version lacks enough depth.
